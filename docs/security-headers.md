# Browser security headers and CDN migration plan

## Current production policy

All static Pages roots receive the shared `_headers` policy generated by
`scripts/create-velverahub-apps.mjs`. The local Express preview mirrors the
same policy for HTML responses in `server.js`.

The policy currently:

- blocks framing with `frame-ancestors 'none'` and `X-Frame-Options: DENY`;
- disables camera, microphone, geolocation, and payment browser permissions;
- limits referrer detail to the destination origin on cross-origin requests;
- blocks plugins and unsafe base URLs;
- limits scripts, styles, connections, images, media, workers, and manifests to
  the app plus the explicitly required Supabase, font, and CDN origins.

`'unsafe-inline'` and the two CDN origins remain temporarily because the
vanilla storefront currently contains inline page scripts and loads
Supabase/Font Awesome from third-party CDNs.

## Replacing third-party scripts

Before removing the temporary CSP exceptions:

1. Pin the exact Supabase JS and Font Awesome versions in a lockfile or asset
   manifest; do not use floating `@2` or unversioned CDN URLs.
2. Download and review the production browser bundles into a versioned
   `assets/vendor/` directory, preserving license notices and integrity hashes.
3. Replace every CDN script/style reference in the source HTML and generated
   roots with the reviewed local files.
4. Move remaining inline page scripts into external modules. If a small inline
   bootstrap must remain, generate a per-response nonce in the Express
   preview and use the equivalent Pages deployment mechanism.
5. Remove CDN hosts and `'unsafe-inline'` from `script-src`/`style-src`, then
   verify auth redirects, Supabase requests, image transformations, checkout,
   video playback, and seller uploads under the stricter policy.
